# Nerdlab Candy — React library

The library is a **thin layer on top of CSS**: each component sets `nl-*` classes, and all the visuals come from the skin stylesheet. Switching skins means switching stylesheets.

## Install from GitHub Packages

The packages are published to GitHub Packages under the `@robin-dot-lab` scope. Add this to your project's `.npmrc`, with a GitHub token that has the `read:packages` scope in `GITHUB_TOKEN`:

```ini
@robin-dot-lab:registry=https://npm.pkg.github.com
//npm.pkg.github.com/:_authToken=${GITHUB_TOKEN}
```

Then install the library and the skin:

```sh
pnpm add @robin-dot-lab/react @robin-dot-lab/css-candy
```

## Usage

```tsx
// Full rendering, Google Fonts included
import '@robin-dot-lab/css-candy/fonts.css';
import '@robin-dot-lab/css-candy/candy.css';

// Or with no call to Google: import only candy.css and declare
// Bricolage Grotesque, Outfit, Space Mono and Silkscreen yourself.
import '@robin-dot-lab/css-candy/candy.css';

import { Button } from '@robin-dot-lab/react';
```

## Dark theme

Set `data-theme="dark"` on `<html>`. The **Theme** switcher in the toolbar does exactly that.

## Overriding a style

The whole skin lives in the `nl.*` cascade layers: any **unlayered** CSS rule from the application wins, whatever its specificity.

## Client and server components

`Button`, `Badge`, `Card` and `Window` have no state and no effects: they work as server components. `Field`, `Input` and `Tabs` carry `"use client"`.
